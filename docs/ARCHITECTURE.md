# 架构与设计取舍

## 主线

1. Android 导入文件或从可选设备外围桥获得录音。
2. 上传到主 API，保存原声、标记、来源和账号归属。
3. Gemini 产生声音语义和创作建议；指定哼唱用 pYIN 分析音高，形成 ABC。
4. 用户确认曲风、中文描述、seed 和可选乐谱。
5. 文字翻译与 YuE2 生成在独立服务执行，任务结果通过后端返回。
6. 生成歌曲可以用 Demucs 分六轨，在 Web Audio 中试听编辑，最后由音频服务导出。

## 为什么拆分

设备能力需要原生层和授权组件；音频算法、模型 API 与 GPU 环境有不同依赖。使用界面、业务、GPU 适配分离，允许替换部分模块，同时让来源与任务状态可追溯。

当前使用单进程串行任务执行，不是可水平扩展的任务平台。实际服务器路径、GPU 锁和超时仍有部署约定，后续需要配置化、持久任务队列与重启恢复。

## 身份与数据

业务用户身份来自账号服务验证，不能接受客户端任意 `owner_id`。权限覆盖列表、原声、结果直链、变更操作、生成输入引用、六轨项目和导出文件。

退出会话会被撤销。切换账号需要同时处理网页数据、播放器缓存、原生网络排队请求和设备会话；仅隐藏 UI 列表不能构成隔离。

## 音频事实边界

原生活音频不是 YuE2 直接波形条件：生活素材通常转成语义描述，哼唱用 ABC 作为可选参考。原始素材独立保存供回听，不保证原始采样出现在成品中。Demucs 输出为分离估计，不能宣称每条都没有串音。
